# انطلاقة — النشر على Render

خادم Node واحد يقدّم الموقع ولوحة التحكم ويحفظ الحجوزات في PostgreSQL. نفس الواجهة السابقة بدون أي تغيير في السلوك.

## النشر (٥ دقائق)
1. ارفع هذا المجلد إلى مستودع GitHub جديد.
2. في render.com: **New → Blueprint** → اختر المستودع. سيقرأ `render.yaml` وينشئ الخدمة وقاعدة البيانات تلقائياً.
3. عند الطلب أدخل `ADMIN_EMAIL` و `ADMIN_PASSWORD` (8 أحرف فأكثر). يُنشأ حساب المدير تلقائياً عند التشغيل.
4. افتح الرابط، جرّب الفورم، ثم «تسجيل الدخول» → الداشبورد.

الجداول (`bookings` و `users`) تُنشأ تلقائياً عند أول تشغيل.

## إضافة أعضاء الفريق
من Render → الخدمة → **Shell**:
`npm run user -- member@example.com كلمة_المرور_الطويلة team`
(الدور `admin` يرى زر تصدير CSV، و`team` للمتابعة فقط.) نفس الأمر يغيّر كلمة مرور مستخدم موجود.

## ملاحظات
- `/api/bookings` · `/api/login` · `/api/me` · `/healthz` هي نقاط الخادم، والواجهة تستدعيها كما هي.
- الجلسة كوكي موقّع HttpOnly لمدة 7 أيام، وكلمات المرور مشفّرة (scrypt)، وهناك حد لمحاولات الدخول والحجز.
- قاعدة Render المجانية لها مدة صلاحية محدودة والخدمة المجانية تنام عند الخمول (أول طلب بطيء). للإنتاج اختر خطة مدفوعة من `render.yaml`.
- لاستخدام قاعدة أخرى (مثل Supabase) ضع رابط الاتصال في المتغيّر `DATABASE_URL` بدل قاعدة Render.
